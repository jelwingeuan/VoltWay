## Why this matters

VoltWay currently saves an entire private charger, including its precise coordinate, into the invitee's own `favorite_stations` row. Revoking the invitation or deleting the site removes discovery access but not that saved copy. Hiding the stale favorite in SwiftUI does not remove the coordinate from the Data API. Private favorites must be ID-only and resolve solely from sites the user can access now; existing saved private snapshots must be scrubbed.

## Steps

### Step 1: Make the database incapable of retaining private favorite snapshots

Generate a new migration with `supabase migration new private_favorite_snapshots`. In one migration: drop `NOT NULL` from `favorite_stations.station_snapshot`; set existing snapshots to SQL `NULL` where `station_id` starts with `private:` or `station_snapshot->>'source' = 'ownerProvided'`; add a CHECK constraint requiring `station_snapshot IS NULL` for any such row. Preserve public snapshots unchanged. Use the existing SQL style and do not rewrite past migrations.

**Verify**: `rg -n 'drop not null|station_snapshot = null|ownerProvided|private:|check' supabase/migrations/*private_favorite_snapshots*.sql` → all four operations appear. Start the disposable local stack with `supabase start`, then `supabase db reset --local` → exit 0 with the new migration applied. Never run reset with `--linked` or a remote `--db-url`.

### Step 2: Encode a private favorite as ID plus explicit null snapshot

Change `FavoriteStation.stationSnapshot` to `ChargingStation?` while preserving decoding of old public rows. Ensure the POST payload for `private:` / `.ownerProvided` sends JSON `"station_snapshot": null` explicitly, including on upsert; merely omitting an optional key may preserve an old full snapshot. In `VoltWayStore.toggleFavorite`, keep the optimistic private favorite ID but never attach the station object. `rebuildFavorites` must resolve an ID from current `stations`; it may use a fallback snapshot only when one exists and is a public/partner source. A revoked private site must stay out of `favoriteStations` even if the ID bookmark remains.

**Verify**: `rg -n 'stationSnapshot|station_snapshot|ownerProvided|private:' VoltWay/Models.swift VoltWay/Services.swift VoltWay/AppStore.swift` → nullable handling exists at every encode/decode and fallback site. Swift test command → exits 0.

### Step 3: Add regression tests for before and after revocation

In `VoltWayTests/VoltWayTests.swift`, following the existing mock URL tests, assert: private favorite POST contains its ID and explicit `station_snapshot: null`; a nullable private favorite decodes; a legacy public favorite with a full snapshot still decodes and appears according to current fallback rules; after a station disappears from the RLS-filtered response, its private favorite is not shown or handed to CarPlay. Create `supabase/tests/private_favorite_storage.sql` as a pgTAP test (see [Supabase database testing](https://supabase.com/docs/guides/database/testing)): using disposable local auth users, insert a private site and ID-only favorite, revoke the invite, impersonate the former invitee, and assert their favorite row's `station_snapshot IS NULL`; assert a non-null private favorite insert/upsert fails. Include a public favorite control row whose snapshot remains readable. For the backfill gate, create `supabase/fixtures/legacy_private_favorite.sql` with only synthetic owner/user IDs and a private favorite containing a dummy coordinate. On a disposable local stack run `supabase db reset --local --version 202609280004` (the last existing migration before this plan), insert the fixture using `psql` and the **local** DB URL shown by `supabase status`, then `supabase db push --local` to apply the new migration without wiping the fixture. Query `select count(*) from public.favorite_stations where (station_id like 'private:%' or station_snapshot->>'source' = 'ownerProvided') and station_snapshot is not null;` via local `psql`; expect `0`. Discover exact CLI flags with `--help` before running; never use `--linked` or a remote database URL.

**Verify**: Swift test command → all pass. On a disposable local Supabase stack, `supabase db reset --local`, then `supabase test db supabase/tests/private_favorite_storage.sql` → exit 0 and `Result: PASS`. Separately run the pre-migration fixture sequence above; the backfill query returns `0`. Do not claim live RLS verified without a configured project.

## Maintenance notes

Any future offline-Saved feature must not reintroduce private coordinates in `favorite_stations`, UserDefaults, or CarPlay cache. A previously invited person may already have seen/copied a coordinate; this change prevents ongoing storage/access through VoltWay, not reversal of prior knowledge.
